## 飞书 Wiki / 在线文档接入

1. 在飞书开放平台创建企业自建应用，把 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 写入服务器 `/opt/northstar/backend/.env`。
2. 为应用开通 `wiki:wiki:readonly` 与 `docx:document:readonly`，发布应用版本。
3. 在飞书知识空间或具体文档的权限设置中，将应用加入可访问范围。只开 API 权限但未共享文档，仍会读取失败。
4. 重启服务后，在“知识库 → 飞书 / 在线文档”中一次粘贴一个或多个 `wiki/docx/docs` 链接。
5. 未配置或授权失败时，NorthStar 会保留数据源和同步错误，方便修复后重试。临时方案是导出 DOCX/XLSX 后批量上传。

## 服务器更新

不要运行旧的一键部署脚本：它会重写现有 Nginx 配置。不要替换数据库、backend/data、.env 或现有证书。

1. 将更新后的源码上传至 `/opt/northstar`，只更新源码文件，保留运行数据。
2. 在服务器构建前端：

```bash
cd /opt/northstar/frontend
npm ci
npm run build
```

3. 在 `/opt/northstar/backend/.env` 中配置 `HUNYUAN_API_KEY`（不要发到聊天或提交到 Git）。可保留现有 `HUNYUAN_BASE_URL` 和 `HUNYUAN_MODEL`。飞书导入需要 `FEISHU_APP_ID`/`FEISHU_APP_SECRET`，应用需要相应文档读取权限及文档共享。
4. 在 NorthStar 的 Nginx HTTPS server 块中添加 `client_max_body_size 12m;`，先备份配置，再运行 `sudo nginx -t && sudo systemctl reload nginx`。保留 Certbot 的全部配置。
5. `sudo systemctl restart northstar`。启动会新增知识库表，不删除或覆盖旧表。

## 验证清单

- 登录账号 A，上传自己的真实 Word/Excel，查看切片，刷新页面确认资料仍在。
- 登录账号 B，确认看不到账号 A 的资料。
- 配置模型后，对一段真实竞品字幕点击 AI 整理，核对钩子、主体、CTA 和关系图引文。
- 在 Cue 中提出能从资料回答的问题，展开来源核对原文。再追问确认多轮历史被带入。
- 删除文档后，确认它的片段不再被检索。
- `sudo certbot renew --dry-run` 确认原有证书续期正常。

自动测试：`PYTHONPATH=backend python -m unittest discover -s backend/tests -v`。
